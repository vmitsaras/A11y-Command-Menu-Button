Plugin example

Status announcement formatter for command menus

A support team command menu announces activated, unavailable, and loading commands through one persistent polite status target.

Scenario

A support agent is triaging a customer case. The command menu contains available actions, actions blocked by missing context, and an action that is still preparing.

User goal: choose an action confidently without losing keyboard position or hearing raw ticket metadata.

Try it

  • Open the Actions menu and choose Assign to me.
  • Choose Request legal review to hear the disabled formatter text.
  • Choose Generate summary to hear the loading formatter text.
  • Use Arrow keys, Home, End, Enter, Space, Escape, and typeahead letters.

Code snippets

Live region target

<p
  id="triage-status"
  role="status"
  aria-live="polite"
  aria-atomic="true"
  data-command-announcement-target
></p>

Formatter setup

createCommandMenuButton(root, {
  announce: {
    target: status,
    formatCommand: ({ item }) =>
      item.getAttribute("data-command-announcement") ||
      "Command activated.",
    formatDisabled: ({ item }) =>
      item.getAttribute("data-command-disabled-announcement") ||
      "Command unavailable.",
    formatLoading: ({ item }) =>
      item.getAttribute("data-command-loading-announcement") ||
      "Command is still loading."
  }
});

Accessibility notes

  • The trigger is a real button with a visible text label and menu relationship attributes.
  • Menu items are real buttons with role="menuitem" for an application command menu.
  • The status target is persistent, polite, atomic, and outside the hidden menu panel.
  • Disabled and loading commands remain arrow-key discoverable; announcements never move focus.
  • Repeating the same blocked action requests the same polite status message again.
  • Announcement copy is curated and avoids raw command IDs, file names, or customer data.
  • Motion comes from the package CSS and respects reduced-motion preferences.
  • Manual screen reader checks are still needed for VoiceOver, NVDA, or JAWS release confidence.

Developer notes

  • Root selector: [data-command-menu].
  • Trigger selector: [data-command-trigger].
  • Panel selector: [data-command-menu-panel].
  • Command selector: [data-command-item] with stable data-command-id values.
  • Options used: typeahead: true, closeOnSelect: true, and announce with all three formatters.
  • Limitations: automated tests can verify live-region text updates, not actual assistive technology speech.
